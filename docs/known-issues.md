# 已知问题

## 低优先级：底部 inline 元数据在极窄余量下可能整体下移一行

当第一页底部（或其他页面底部）由多段 inline 元数据组成，且最后一段文字几乎占满剩余宽度时，浏览器在 HTML 预览与图片型 PPTX 导出之间可能出现字体度量差异。导出结果可能把这一整组底部元数据推到下一行。

这只影响局部视觉细节，不影响页数、页面顺序、主要内容、背景保真、普通文本编辑或其他页面导出，也不阻塞公司电脑的访问、编辑和网络零外传测试。

临时处理方式：导出前适当缩短底部元数据、减小该组字号，或给最后一段预留更多横向空间。后续会在导出布局稳定策略中进一步处理多段 inline 内容的整体宽度测量。

## 设计边界：按信息密度设置字号，不做自动全局放大

对任意 HTML 自动把所有文字整体放大，会同时改变换行、卡片高度和时间线间距，容易制造新的溢出或重叠。因此工具不会无条件改写旧稿；字号和对齐改进优先通过新的 LorealGPT 生成规范、新建页默认值与可视化编辑完成。

1920×1080 画布的标准字号档位为：封面主标题 84–96px、普通页标题 58–68px、副标题/强调 40–48px、正文 30–36px、注释/页脚 24–28px、标签/表格 22–24px。稀疏页可以适度放大，密集页正文可以使用 28–32px，但一般不低于 22px。标题、正文、关键数字和注释应分别设定，不能用统一倍率代替层级。

生成 HTML 和导出前都要做版式自检：字号增大时同步扩容文本框或卡片、调整换行策略或重新分栏，并检查重叠、裁切、越界、意外换行、标题与标签重叠及卡片高度不足。双栏应使用明确列边界并至少保留 80px gutter；圆形主视觉、投票框或大图必须在所属列内，不能仍然水平居中而挤压右侧文字。已有页面应按模块逐页调整并运行质量检查。

## 材料解析边界：首版为本地基础提取

首版材料入口只在浏览器本地读取，不上传原文件，提取结果用于生成提示词：

- PDF 只读取可复制的文字层，扫描件不做OCR。
- Word 仅支持 `.docx`，不支持旧 `.doc`，复杂排版和嵌入对象不保证保留。
- Excel 支持 `.xlsx`、`.xls` 读取工作表单元格值，不理解宏、图表语义或复杂公式依赖。
- 文本、Markdown、CSV、TSV、JSON、HTML、XML按文本读取；超大文件可能受浏览器内存和提示词长度限制。
- 任一格式解析失败，都可以复制材料摘要到需求表单继续流程；原文件不会被上传。
