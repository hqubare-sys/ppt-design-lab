# 已知问题

## 低优先级：底部 inline 元数据在极窄余量下可能整体下移一行

当第一页底部（或其他页面底部）由多段 inline 元数据组成，且最后一段文字几乎占满剩余宽度时，浏览器在 HTML 预览与图片型 PPTX 导出之间可能出现字体度量差异。导出结果可能把这一整组底部元数据推到下一行。

这只影响局部视觉细节，不影响页数、页面顺序、主要内容、背景保真、普通文本编辑或其他页面导出，也不阻塞公司电脑的访问、编辑和网络零外传测试。

临时处理方式：导出前适当缩短底部元数据、减小该组字号，或给最后一段预留更多横向空间。后续会在导出布局稳定策略中进一步处理多段 inline 内容的整体宽度测量。

## 设计边界：已导入页面不做自动全局放大

对任意 HTML 自动把所有文字整体放大，会同时改变换行、卡片高度和时间线间距，容易制造新的溢出或重叠。因此工具不会无条件改写旧稿；字号和对齐改进优先通过新的 LorealGPT 生成规范、新建页默认值与可视化编辑完成。

对 1920×1080 画布，推荐使用封面标题 88–120px、页标题 64–88px、小标题 48–64px、正文 40–52px、注释 32–36px；已有页面应按模块逐页调整并运行质量检查。
