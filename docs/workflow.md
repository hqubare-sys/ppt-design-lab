# 工作流与数据流

## 正常用户流程

1. 用户打开GitHub Pages在线版或离线版工具。
2. 用户填写PPT主题、受众、时长、页数、语言、内容材料和视觉方向。
3. 工具在本地生成LorealGPT提示词，并由用户主动复制。
4. 用户在公司批准的LorealGPT中粘贴提示词，先生成大纲并确认故事结构。
5. 工具根据确认后的大纲生成第二段HTML提示词；用户在LorealGPT中生成符合规范的完整HTML。
6. 用户把HTML复制回工具，或从本地导入HTML文件。
7. 工具在隔离环境中解析内容，识别每个幻灯片 `<section>`，并显示缩略图和可视化编辑画布。
8. 用户修改文字、字体、字号、颜色、图片、模块位置和尺寸；工具只在本地更新。
9. 工具运行本地质量检查并提示溢出、越界、小字号、缺图、低对比度和重复页面。
10. 用户导出自包含HTML、图片型PPTX或本地项目文件（默认 `.pptdlab`；打开项目兼容旧版 `.pptdlab.json` / `.json`）。

## 结构化HTML约定

- 画布：1920×1080，16:9。
- 每页：一个直接、独立的 `<section class="slide" data-slide-id="..." data-screen-label="...">`。
- 正文：静态HTML；可编辑文字分别放在叶子元素中。
- 样式：使用CSS变量统一管理字体、字号、颜色、间距和安全边距。
- 内容：不使用React/Vue或脚本循环生成可编辑正文。
- 网络：不依赖外部脚本、字体、iframe或运行时API。
- 图片：导入后优先内嵌或由用户保存在本地项目文件中。

## PPTX导出策略

### 默认：图片型PPTX

- 每个HTML幻灯片在浏览器中以固定尺寸渲染为高清图片。
- 每张图片作为一页全幅内容写入PPTX。
- 优先保证视觉一致性，不承诺对象级编辑。

### 后续：基础可编辑PPTX

- 普通文字、图片和简单色块映射为PowerPoint原生对象。
- 复杂CSS、SVG、Canvas、图表与特殊效果按元素或整页回退为图片。
- 可编辑性不得以破坏版式或泄露内容为代价。

## 数据边界

| 数据 | 所在位置 | 是否进入GitHub |
|---|---|---|
| 工具源码、通用模板、许可证 | 项目根与GitHub仓库 | 是 |
| 用户填写的PPT要求 | 浏览器内存；用户主动保存时进入本机项目文件 | 否 |
| LorealGPT提示词和回答 | 公司LorealGPT会话与用户剪贴板 | 否 |
| 导入的HTML、图片、品牌模板 | 公司电脑本地 | 否 |
| 导出的HTML、PPTX、`.pptdlab` 项目文件 | 公司电脑本地下载目录 | 否 |

## 发布流程

1. 运行项目审计和产品测试。
2. 确认发布包不包含公司内容、测试业务数据或凭据。
3. 发布纯静态工具到GitHub Pages。
4. 同时生成离线ZIP。
5. 在公司电脑验证访问、导入、编辑与导出，并检查网络记录。
