# v0.1 验收标准

## 1. 公司电脑可用

- 在无需管理员权限、无需安装应用的公司浏览器中打开在线版。
- 离线ZIP在允许的浏览器文件策略下可运行；若浏览器限制本地多文件加载，提供自包含单文件版。
- 不要求公司电脑安装Node.js、Python、LibreOffice、浏览器扩展或其他运行时。

## 2. LorealGPT半自动生成

- 非程序员可通过表单生成完整LorealGPT提示词。
- 工具一次生成完整提示词；用户复制到LorealGPT后，LorealGPT在同一次回答中完成内容分析、页面蓝图、视觉规划和自由HTML创作。
- 支持复制提示词、粘贴LorealGPT返回结果和自动提取HTML代码。
- 对缺少幻灯片标记、HTML截断或页数不一致给出人类可读错误和修复提示词。
- 工具不调用LorealGPT API，不读取其登录状态。

### 2.1 首版本地材料读取

- 文本、Markdown、CSV、TSV、JSON、HTML、XML 可以由浏览器直接读取。
- PDF 只提取可复制的文字层，不对扫描件做OCR。
- Word 仅支持 `.docx` 基础文字提取，不支持旧 `.doc`。
- Excel 支持 `.xlsx`、`.xls` 提取工作表单元格值，不解析宏、图表或复杂公式语义。
- 所有文件只在当前浏览器本地读取；解析失败时可以粘贴材料摘要，不影响主流程。

## 3. HTML幻灯片编辑

- 正确识别结构化的多页16:9幻灯片。
- 提供缩略图、翻页、排序、复制、新增和删除页面。
- 支持直接修改文字、字体、字号、字重、颜色和背景。
- 支持拖动与缩放普通模块、替换图片、撤销和恢复。
- 重新打开本地项目文件后保持页面顺序与关键编辑状态。

## 4. 导出

- 导出的自包含HTML可在浏览器中播放并按页导航。
- 图片型PPTX页数、顺序和16:9尺寸正确，视觉与HTML预览基本一致。
- 字体或图片无法保真时，导出前给出明确提示。
- 导出全部在浏览器本地完成，不上传用户内容。

## 5. 隐私与安全

- GitHub仓库和Pages中不包含公司业务内容、品牌资产、用户PPT或生成结果。
- 无统计、遥测、云端错误上报、业务后端或远程数据库。
- 导入HTML中的脚本、事件、iframe和远程资源默认禁用或隔离。
- 初始工具资源加载完成后，导入、编辑、保存和导出测试全过程没有携带用户内容的对外网络请求。
- 发布包经过敏感文件、常见凭据形态和办公文档检查。

## 6. 首页与视觉生成系统

- 首次打开内置示例正好包含三页：工具定位与适用场景、本地四步工作流、高级视觉生成系统示意图。
- 首页示例明确显示“无需安装、手工复制LorealGPT、不连接公司AI、内容只在本机处理”的边界。
- 视觉系统示例包含咨询蓝、黑金、暖米三套主题；展示十种页面结构原型、25+视觉模块的四大模块组和页面蓝图字段。
- 页面蓝图至少能表达页面目标、核心结论、结构、模块、数据、文案和视觉风格；自由HTML由LorealGPT在同一次生成中返回。
- 首页示例只使用通用说明，不包含公司业务事实、公司Logo、人员、客户或真实PPT内容。

## 7. 治理与交付

- `README.md`、`AGENTS.md`、工作流、验收标准和实现保持一致。
- `python3 scripts/audit_project.py` 返回成功。
- YYOB `PRJ-012` 记录当前版本、里程碑和项目级下一步；Dashboard由生成器派生。
- 公司电脑真实环境验收结果有可复现记录，但不包含公司敏感内容。

## 8. 当前验证记录（2026-08-23）

- 已通过静态源码、隐私边界、iframe sandbox 和测试 fixture 检查。
- 已通过全部应用 JavaScript 语法检查。
- 已在本机浏览器验证内置三页演示、桌面布局、LorealGPT完整提示词、恶意 HTML 清洗、三页识别、页面新增与撤销。
- 已在本机浏览器实际执行独立 HTML 与图片型 PPTX 导出；PPTX 为整页图片，不承诺对象级编辑。
- 已修复自带翻页脚本 HTML 的导入兼容：通用 3 页 fixture 中的 3 个导航圆点未被误识别为页面，第 2、3 页可独立显示。
- 已用用户本地提供的一份 8 页 LorealGPT HTML 验证：准确识别 8 页，第 2 页可见，选中文字后字号、字体、颜色、位置与尺寸等编辑控件正常出现；该业务内容未写入项目测试或文档。
- 已修复页面 CSS ID 不匹配：仅含 `data-slide-id="slide-08"` 的页面会自动获得 `id="slide-08"`；同一份本地 8 页 HTML 的第 8 页标题恢复为 40px 和绝对定位，流程区及三张详情卡恢复横向布局。复制页的 `id` 与 `data-slide-id` 会同步生成新的唯一值。
- 已修复章节标签与主标题重叠：页面根下的 `.section-label` 统一进入顶部 20px 安全区；同一份本地 8 页 HTML 的第 2、3 页经浏览器截图验证，章节标签与主标题已分离，正文布局未被推移。
- 已修复图片型 PPTX 渲染失真：导出宿主由 Shadow DOM 改为无脚本离屏 iframe；通用 `:root` 变量回归页验证页面背景、主题色、白色卡片、边框、圆角与阴影全部保留。
- 已修复导出文字与背景保真：导出前仅对原本无显式换行且实际单行的叶子文字加入 `nowrap` 稳定样式，避免中文短标题尾字换行；导出背景改为读取页面实际计算背景，透明页面才回退到 body、html 或白色，渐变继续由页面 CSS 绘制。
- 已修复编辑交互边界：双击带子元素的结构容器只选择、不进入 `contenteditable`；小于 6px 的指针移动不会写入定位；真正拖动嵌套模块时按其实际 `offsetParent` 坐标计算，避免模块跳出父卡片。通用编辑交互 harness 覆盖上述场景及浅米色背景保留。
- 待验证：公司电脑的访问策略、下载策略、字体表现、真实复杂页面性能，以及浏览器网络记录中的零内容外传。

## 9. GitHub Pages 发布

- `.github/workflows/pages.yml` 仅使用官方 GitHub Pages actions，在 `main` push 或手动触发时发布 `app/` 目录。
- Pages artifact 的根目录就是 `app/`，发布后的站点根路径直接打开 `app/index.html`。
- workflow 使用最小权限：`contents: read`、`pages: write`、`id-token: write`，并用 `pages` concurrency 避免并发部署互相覆盖。
- 公开仓库和 Pages 只包含工具框架、通用测试与说明；公司 HTML、PPT、图片、品牌资产和 LorealGPT 内容不上传。
- Pages 版必须在公司电脑真实浏览器中完成导入、编辑、保存、HTML/PPTX 导出，并用网络记录确认没有携带用户内容的对外请求。

低优先级视觉限制记录在 [`docs/known-issues.md`](known-issues.md)：第一页底部类似多段 inline 元数据在极窄余量下，图片型 PPTX 导出可能把整组内容下移一行；不阻塞公司电脑可用性测试。
